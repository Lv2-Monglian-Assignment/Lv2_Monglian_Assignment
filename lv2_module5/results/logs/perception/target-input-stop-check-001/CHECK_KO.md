# 카메라 입력 중단 후 무발행 관측

## 실험 환경과 목적

Pi D435 컬러 노드를 정상 종료하고 PC target_detector는 유지했다. DOMAIN 30/Cyclone/SUBNET, Pi IP 추가 지정, PC Wi-Fi XML을 동일하게 사용했다. 카메라 입력이 끊기면 과거 결과를 재발행하지 않는지 확인한다.

## 계획한 방법과 실제 수행 방법

정상 입력의 header 10쌍·미검출 0·현재 QoS를 먼저 확인했다. 카메라 실행창에서 Ctrl+C를 직접 입력했고 PID 7483의 정상 종료·센서 닫힘·SSH 종료를 확인했다. 이후 PC 확인창에서 /target 직접 info에 이어 --once --timeout 15의 echo를 직접 실행했다. PC 검출 노드는 유지했다.

## 결과

- [정상 입력 사전 확인](../target-header-check-002/CHECK_KO.md): 10쌍 대조 통과.
- [카메라 종료 로그](../practice_records/pi-camera-stop-input-test-001-received.log): PID 7483 정상 종료.
- [관측 판정](result.json): 발행자 target_detector 1개, Best-effort / Keep-last 1 / Volatile.
- info 다음 echo 구간에 header·point·오류·Ctrl+C 출력 없이 pa12 프롬프트로 돌아왔다.
- 읽기 전용 후속 조회에서 검출 PID 45277의 실행을 확인했다.
- 카메라 중단 후 15초 상한 관측 구간에서 이전 결과의 반복 발행이 관측되지 않았다.

## 해석 및 한계

검출 프로세스가 유지되고 발행자 발견이 동작하는 조건에서 이번 무발행 관측을 통과했다. 정상 영상에서 목표가 없을 때 발행한 0 메시지와 입력 자체가 없을 때의 무발행을 구분했다. 종료 코드는 별도로 저장하지 않았으며 장기 무발행·네트워크 손실률·30fps 안정성 증명은 아니다. 실제 카메라 케이블 단절·재연결과 모든 장애 경로를 시험한 것은 아니다.

ROS 인터페이스 단계는 확인한 범위에서 완료했다. 진행률은 기존 7단계 중 5단계, 약 71%다. 독립 대상 30프레임·없음 10프레임 평가 및 팀 제출 증빙은 남아 있다.
