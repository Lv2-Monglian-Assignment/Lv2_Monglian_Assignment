# 이슈 #34 고정 설정 컬러 부분 재검출

## 실험 환경

Ubuntu PC 시스템 OpenCV 4.6.0. 실제 D435에서 촬영한 대상 있음 30장과 사람 판정 JSON을 사용했다. 원본 데이터셋·촬영 코드·사진 30개 해시와 순서를 재확인했다. 별도 읽기 전용 작업 공간 `Lv2_issue34`의 `docs/perception-issue34` 브랜치에서 설정·검출 코드를 복사했고 원본은 수정하지 않았다.

## 실험 목적

발제 문제 1의 HSV 검출·후보 선택·정규화 출력과 이슈 #34 실행 조건을 대조한다. 이전 설정의 30/30 결과를 새 설정 성능으로 재사용하지 않는다.

## 계획한 방법

HSV [102,120,40]~[110,255,255], 커널 5, 면적 100 px², 크기 판정 2~30 cm², priority, 번호 유지 재선택 0.5초를 고정한다. 원본에 없는 깊이·CameraInfo·관절 자료를 만들지 않는다. 새 선택 윤곽은 사람이 별도로 판정한다.

## 실제 수행 방법

[평가 코드](../../../../scripts/evaluate_issue34_color_frames.py)가 [고정 소스](source/)의 `detection.py`를 읽고 rgb8로 변환한 실제 사진을 처리했다. 크기 판정 설정은 true지만 깊이가 없으므로 해당 코드의 규칙대로 크기 미검증 후보를 남겼다. CameraInfo도 없어 ROS 노드의 fallback과 동일하게 priority만 실행했으며 ObjectTracker는 실행하지 않았다. 실제 거리 우선순위·번호 유지·0.5초 재선택이 검증된 결과가 아니다.

## 결과

- [evaluation.json](evaluation.json): 30장 모두에서 후보 선택. 올바른 목표 선택의 사람 판정 전이므로 TP/FN·검출률은 null이다.
- 원본/마스크/검출 이미지 90장, [프레임 CSV](frames.csv), 설정·소스 SHA256·브랜치/커밋 보존.
- 실제 30장 각각에서 rgb8 경로와 동등한 bgr8 경로의 마스크·좌표 결과가 일치했다.
- [사람 판정 화면](index.html): 초록 윤곽이 실제 목표인지 30장 판정 후 `issue34-overlay-review.json` 저장. 기존 대상 있음 판정은 물체 존재의 증거이고 이번 후보 선택의 정답 판정을 대신하지 않는다.
- 대상 없음 10장 미촬영. 전체 40장 평가·인지 6단계는 미완료다.

## 해석 및 한계

깊이와 관절 정보가 없는 컬러 부분 평가다. 전체 이슈 #34 설정의 실물 성능·처리 FPS·실제 크기·회전 중 번호 유지 성능으로 제출하지 않는다. 새 실물 시험은 같은 목표·거리·조명·배경을 고정하고 동시 깊이/CameraInfo/관절 증거를 수집해야 한다. 검사 이후 원본 브랜치 파일의 해시 불변을 확인했다.

실행 도구: Codex 터미널. 목표 존재 라벨은 기존 사람 판정 자료를 사용했다.


## 선택 결과 사람 판정

설정·원본 데이터셋·사진 30장 해시와 순서를 재검증했다. 초록 윤곽의 실제 목표 선택을 30장 모두 사람 판정으로 확인했다. 컬러 부분 평가 TP 30/FN 0, 대상 있음 선택 성공률 100%다. `human-evaluation.json`과 `human-evaluation.csv`에 저장했다. 원래 예측 `evaluation.json`은 보존한다. 크기 검증·번호 유지·Pi 처리 FPS는 확인하지 않았고, 대상 없음 10장이 없어 전체 40장 평가는 미완료다.
