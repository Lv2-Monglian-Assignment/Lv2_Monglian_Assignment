# Pi 검출 결과의 PC 수신 검토

## 실험 환경

Pi D435 RGB8 640×480·요청 30fps, Pi OpenCV 4.10·Lyrical·Cyclone DDS·DOMAIN 30이다. 검출 소스와 YAML은 기존 PC 판과 동일한 사본이다. PC는 Image를 추가 구독하지 않고 PointStamped만 관측했다.

## 실험 목적

큰 컬러 영상을 PC로 전송하는 조건의 지연을 피하면서 같은 인지 계산과 출력 인터페이스를 유지할 수 있는지 확인한다.

## 계획한 방법

Pi 카메라와 Pi 검출 노드를 실행하고 PC에서 /target을 10초 관측한다. Pi 안에서 입력·출력 header 10쌍을 대조하고 같은 실제 사진의 PC·Pi 계산을 비교한다.

## 실제 수행 방법

명시적으로 맡긴 인지 작업 범위에서 Codex 터미널 도구로 실행했다. 같은 소스·설정 사본을 Pi의 별도 폴더에 배치했다. 원본 PC 검출 소스·YAML을 변경하지 않았고 모터 명령은 실행하지 않았다.

## 확인 결과

PC에서 /target 297개·약 29.879Hz를 관측했고 최대 도착 간격은 약 0.0865초였다. source stamp는 단조 증가했고 무효 메시지는 0개였다. 실제 단일 target_detector 발행 QoS는 Best-effort·Keep-last depth 1·Volatile이며 지정한 짧은 수·간격·형식 기준을 통과했다.

Pi 로컬 header 대조 10쌍에서 stamp·frame_id 불일치는 0개였다. 해당 구간은 검출 중이라 비영 값 10쌍이며 미검출 0 시험과 구별한다. [원본 header 결과](../pi-local-header-001/result.json)를 연결한다.

Pi 입력 10초 관측은 293개·도착 약 29.993Hz, 최대 도착 간격 약 0.0358초, 형식 640×480 rgb8이다. [입력 근거](../pi-local-input-001/result.json)는 생성된 전체 프레임 수가 아니라 해당 로컬 구독에서 받은 수다.

같은 실제 PNG에 대해 PC OpenCV 4.6과 Pi 4.10의 마스크 해시와 좌표가 일치했다. [대조 기록](cross-opencv-check.json)에 해시와 원본 값이 있다.

## 해석 및 한계

이 구성의 짧은 관측에서 인지 입력과 PC 결과 전달을 확인했다. 큰 영상 전송을 제거한 실행 위치 변경이며 Wi-Fi·DDS 근본 원인 확정을 뜻하지 않는다. 10초 관측은 장기 안정성이나 전체 프레임 무손실을 보장하지 않는다. 같은 사진 한 장의 버전 대조는 모든 입력에 대한 동일 동작 증명도 아니다. 실제 30·10프레임 정답 라벨 평가는 별도로 남아 있다.
