# PC 검출 중단 조건의 Pi 영상 관측 비교

## 실험 환경

Pi 카메라 PID 1781과 RGB8 320×240·6Hz 요청 프로파일을 유지했다. ROS Lyrical·Cyclone DDS·DOMAIN 30이다. 앞선 시험은 PC target_detector가 실행 중이었고 이번 시험은 TERM 종료 후 프로세스 부재를 확인한 상태다. 다른 모든 영상 구독자 부재를 입증한 것은 아니다.

## 실험 목적

발제 문제 2의 영상 입력 → /target 경로에서 PC 검출의 영상 구독 유무와 Pi 로컬 수신 변화의 관계를 확인한다.

## 계획한 방법

카메라 설정과 Pi 관측 코드를 유지하고 PC 검출을 중단한 조건에서 Pi Image를 같은 10초 동안 관측한다.

## 실제 수행 방법

PC 확인창에서 SSH 명령을 터미널에 직접 입력했다. 종료 후 result.json과 observe_source.py를 읽기 전용으로 복사·대조했다. 카메라 PID 1781 유지와 PC 검출 부재를 읽기 전용으로 재조회했다. 원격 파일 조회·기록 정리는 Codex로 수행했으며 추가 실습 명령은 대신 실행하지 않았다.

## 확인 결과

| 항목 | PC 검출 실행 중: 관측 002 | PC 검출 중단: 관측 003 |
|---|---:|---:|
| Pi Image 수 / 10초 | 32 | 58 |
| 첫·마지막 도착 사이 빈도 | 3.33221Hz | 5.98869Hz |
| 관측 header stamp 빈도 | 3.71171Hz | 5.98697Hz |
| 최대 도착 간격 | 0.60106초 | 0.16908초 |
| 최대 관측 stamp 간격 | 0.50112초 | 0.16704초 |

003의 첫 도착은 시작 후 약 0.322초, 마지막은 약 9.840초다. 실제 관측 시간은 약 10.001초, 형식은 320×240 rgb8, frame_id는 camera_color_optical_frame, 관측 stamp는 단조 증가했다. 호스트의 IP 재조립 실패·시간 초과 및 UDP 수신 오류·버퍼 오류 차분은 모두 0이다. status=complete·error=null이며 로컬·원격 사본·결과의 소스 해시가 일치한다.

## 해석 및 한계

이번 구독 관측 범위에서는 요청 6Hz에 가까운 Pi 수신을 확인했다. 카메라가 지속적으로 6Hz 영상을 제공할 수 없는 고장이라고 판단할 근거는 없다. PC 검출 중단과 Pi 로컬 관측 개선이 같은 조건 비교에서 나타났다. PC로의 영상 전달 조건이 영향을 줄 가능성이 있지만 Wi-Fi 품질·DDS 발행 동작·프로세스 부하·측정 시점 변화 중 정확한 원인은 확정하지 않는다. 실제 카메라 생성 프레임 전체를 기록한 것이 아니므로 무손실이나 전체 프레임 수를 보장하지 않는다. 이 10초 결과는 장기 안정성·640×480 30Hz 복구·독립 정확도 평가 완료를 뜻하지 않는다.

다음은 카메라와 설정을 유지한 채 PC 검출을 같은 명령으로 다시 시작한다. IMAGE_RECEIVED 출력 확인 후 별도 단계로 같은 Pi 관측 004를 진행해 실행→중단→재실행 순서에서 변화가 반복되는지 확인한다. 새 노드 시작은 준비 상태, 새 영상 처리 로그는 실제 입력 수신으로 구분한다. 재시작·추가 관측은 아직 실행 전이다. 전체 진척은 기존 증거 기준 5/7, 약 71%다.
