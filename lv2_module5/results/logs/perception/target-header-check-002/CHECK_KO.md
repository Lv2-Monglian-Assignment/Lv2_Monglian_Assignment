# 입력·출력 header와 발행 QoS 대조 통과

## 실험 환경과 목적

Pi D435 RGB8 640×480·30fps 요청 프로파일, PC 검출 노드, DOMAIN 30/Cyclone/SUBNET, Pi IP 추가 지정과 PC Wi-Fi XML을 사용했다. 입력 Image와 출력 PointStamped의 header 유지·미검출 0·실제 발행 QoS를 확인한다.

## 계획한 방법과 실제 수행 방법

카메라·검출 실행창을 유지하고 PC 확인창에서 동일 tools/check_target_headers.py와 10쌍 기준을 사용했다. 첫 시험의 수신 쌍 수 부족을 확인한 뒤 --timeout만 20에서 45로 늘리고 새 출력 폴더를 지정해 직접 재시험했다. 검출기·HSV 설정은 변경하지 않았다.

## 결과

| 시험 | 대기시간 상한 | 대조 쌍 | header 불일치 | 비영·유효하지 않은 대조 출력 | 발행 QoS | 전체 판정 |
|---|---:|---:|---:|---:|---|---|
| [첫 결과](../target-header-check-001/result.json) | 20초 | 8/10 | 0 | 0 | 통과 | 미통과: 쌍 수 부족 |
| [재시험](result.json) | 45초 | 10/10 | 0 | 0 | 통과 | 통과 |

- 관측 Image 12개, PointStamped 13개 중 같은 stamp의 10쌍을 대조했다.
- 대조된 입력은 모두 rgb8 640×480이다. stamp와 frame_id=camera_color_optical_frame이 출력에서 그대로 일치한다. 출력 point는 모두 0이다.
- 실제 발행자는 target_detector 1개, Best-effort / Keep-last 1 / Volatile이다.
- 미대조 입력 header 2개, 출력 header 3개이며 캐시 퇴출은 0이다.
- [실행 소스 사본](check_source.py)의 SHA-256은 `b6817e92de0538515e3a7359b74a908d230188af17c05955644b1ed1ed0721bf`로 결과 메타데이터·첫 시험 소스·현재 도구와 일치한다.

## 해석 및 한계

계획한 10쌍에서 header 유지·미검출 0과 실제 발행 QoS를 확인했다. 관측되지 않거나 대조되지 않은 모든 프레임의 손실률·처리율은 평가하지 않았다. 45초는 대기시간 상한이며 실제 소요 시간이나 실측 FPS가 아니다. 입력 관찰용 추가 영상 트래픽도 있다. 장기 안정성 및 독립 대상 30/없음 10프레임 정확도 평가 완료를 의미하지 않는다.

다음 계획: Pi 카메라 실행창에서 Ctrl+C로 카메라를 정상 종료하고 종료 로그·프롬프트를 확인한다. PC 검출 노드는 계속 실행한다. 이후 입력 중단 상태에서 /target가 이전 결과를 반복 발행하지 않는지 별도 관측한다. 카메라 중단과 중단 후 관측은 아직 수행 전이며 진행률은 4/7, 약 57%다.
